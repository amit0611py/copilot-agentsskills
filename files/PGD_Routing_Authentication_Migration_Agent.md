# PGD Application — Routing + Login Redirect + Authentication Migration

## Objective

Modify the existing PGD application so that authentication and routing use clean browser URLs instead of hash-based routing and URL query tokens.

### Architecture

```text
Browser
   ↓
WAF
   ↓
API Gateway
   ↓
WildFly
   ↓
Spring Boot
   ↓
React application
```

The React production build is packaged inside the Spring Boot application's `static` directory.

**Do NOT assume WAF or API Gateway changes are required.**

The first objective is to solve this at the React + Spring application level.

# CURRENT PROBLEM

The application currently starts at:

```text
https://paymentproject.infun.com/pgd
```

This does not open correctly.

When using:

```text
https://paymentproject.infun.com/pgd/
```

the application redirects to:

```text
https://paymentproject.infun.com/pgd/#/login
```

The application therefore currently uses hash-based routing.

After successful login, the application redirects to:

```text
https://paymentproject.infun.com/pgd?token=XXXXX
```

This URL fails.

If `/` is manually inserted before `?`:

```text
https://paymentproject.infun.com/pgd/?token=XXXXX
```

the application works.

This missing-slash issue MUST be investigated and fixed.

However, do NOT simply patch the URL by adding `/`.

The desired final architecture removes the token from the URL entirely.

Expected flow:

- NO `#`
- NO authentication token in the URL
- NO authentication session ID in the URL

# LOGOUT

Logout must:

1. Invalidate the server-side session.
2. Clear/invalidate authentication cookies appropriately.
3. Clear frontend authentication state.
4. Navigate to:

```text

```

5. Ensure subsequent protected API calls fail authentication.
6. Ensure the user cannot continue using protected functionality.
